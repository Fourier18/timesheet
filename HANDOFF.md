# Timesheet — Project Handoff / Technical Log

A standalone reference for the Timesheet desktop app, meant to complement the
git history. If you're picking this up cold, this file is the source of truth
for *why* things are the way they are. The committed source is the source of
truth for *what* the code does.

---

## 1. What it is

A local, offline desktop **time-tracking app** built with **Electron**. You
clock in (with an hourly rate), optionally take breaks, clock out, and the app
tracks hours and computes earnings. All data lives in a single local JSON file —
no server, no account, no network.

- **Platform:** Windows (built/tested here); Electron is cross-platform but only
  the Windows NSIS installer target is configured.
- **Repo:** https://github.com/Fourier18/timesheet (public)
- **Version:** 1.0.0

---

## 2. Tech stack

| Piece | Choice | Notes |
|---|---|---|
| Shell | Electron `^33` | `main` process + `preload` bridge + renderer |
| Packaging | electron-builder `^25.1.8` | Windows `nsis` target, one-click per-user |
| UI | Vanilla HTML/CSS/JS | No framework, no bundler, no deps at runtime |
| Storage | Local JSON file | Atomic writes in Electron `userData` dir |
| Icon | Generated at build time | `scripts/gen-icon.js`, zlib only, no image libs |

Security posture: `contextIsolation: true`, `nodeIntegration: false`. The
renderer never touches Node/fs directly — everything goes through a small
`window.api` exposed by `preload.js` via `contextBridge`.

## 4. Data model & persistence

**File:** `app.getPath('userData')/timesheet.json`
→ on Windows: `%APPDATA%\timesheet\timesheet.json` (Roaming).
The folder name is the lowercase package `name` ("timesheet").

**Schema (v2):**
```jsonc
{
  "version": 2,
  "activeTask": { "id": "uuid", "rate": 50, "startedAt": "<local-ISO>" } | null,
  "sessions": [
    {
      "id": "uuid",
      "taskId": "uuid",          // groups sessions belonging to one clock-in→out task
      "start": "2026-06-02T19:48:35.515-04:00",  // local-offset ISO 8601
      "end":   "2026-06-02T19:48:39.439-04:00" | null,  // null = still open
      "notes": "",
      "rate":  33                // $/hr, stored per session
    }
  ]
}
```

Key persistence decisions:
- **Atomic writes:** write to a temp file then `renameSync` over the real one,
  so a crash mid-write can't corrupt the data file.
- **Local-offset ISO timestamps** (`toLocalISO`), not UTC — this is **DST-safe**
  and keeps timestamps readable in the user's wall-clock time.
- **Midnight-split-on-display** (`splitByDay`): a session crossing midnight is
  split into per-day pieces *for display/totals only*; the stored session stays
  a single start→end record.
- **Single-instance lock:** only one app instance runs; a second launch focuses
  the existing window instead of opening a duplicate (and avoids two processes
  writing the same file).

## 5. Clock state machine

```
        Clock In (rate prompt, ALWAYS blank)
 Idle ───────────────────────────────► Working
   ▲                                    │   │
   │ Clock Out                  Break   │   │ Clock Out
   │                                    ▼   │
   └──────────── OnBreak ◄──────────────┘   │
        ▲           │                       │
        └─ Resume ──┘  (reuses rate         │
           silently)   ───────────────────► Working
                                            │
                                            └─► (Clock Out) → Idle
```

- A **task** = one clock-in→clock-out cycle (`activeTask`). It can contain
  multiple **sessions** (work intervals) split by breaks.
- **Rate is mandatory and prompted blank** on every new clock-in (deliberate —
  do *not* prefill the last rate; this was explicitly requested).
- **Resume reuses the task's rate silently** (no second prompt).
- **Earnings** = hours × rate, computed per session and summed.

## 6. Views & UI behavior

Scope selector (segmented buttons): **Days · Range · All**

- **Days** (`scope:'week'`): shows `state.spanDays` days ending at
  `weekAnchorEnd`. The **total header itself is a dropdown** (`<select
  id="spanSelect">`, options **Day / 3-day / 7-day / 14-day / 31-day total**) —
  changing it sets `spanDays` and re-renders. Prev/next arrows step by
  `spanDays`. Default = 7. *(This is the feature that replaced the old fixed
  "7-day total" text — the header text was made into the dropdown.)*
- **Range:** two date pickers, capped at **31 days** (`MAX_RANGE_DAYS`); the
  range auto-clamps if you pick more.
- **All:** every day that has data, newest first.

**Intervals toggle** (default **ON**): expands each day into per-session rows.
Each row = time range · duration · earnings · a **full-width note input on its
own line** · Edit / Del buttons. Open sessions show a live "now" that ticks.

> Note-input gotcha (fixed): the note field used to share a CSS grid row with
> time/duration/money/buttons and got crushed to ~17px wide on a normal window.
> It's now on its own full-width grid row (`grid-template-areas`) so it's
> actually usable. If you touch `.row` layout in styles.css, keep the note on
> its own line.

**Dialogs:**
- *Clock-in rate dialog:* hourly rate (required, blank) + **optional Note**
  (`rateNote`).
- *Add / Edit entry:* start & end date+time, "currently clocked in" checkbox
  (open session), rate (required), notes. Validation rejects: invalid times,
  end ≤ start, a second open session, rate < 0, and **overlapping sessions**.

**Export:** CSV (one row per session, with date, in/out, hours, rate, earnings,
notes) and full JSON backup. Both go through native save dialogs in `main.js`.

## 7. Theme & design constraints  ⚠️ READ BEFORE RESTYLING

Aesthetic: **"Nostromo" green-phosphor CRT** (scanlines, flicker, vignette,
blinking caret, `> ` prompts) layered over **industrial steel** (beveled
panels, brushed-metal gradients, corner rivets).

**HARD RULE — no orange, no yellow, no amber. Anywhere. Ever.**
Including warning/caution/break states. This was flagged twice and is
non-negotiable.
- Break / paused / "needs attention" → **grey-green "standby"** tone
  (`--standby`), *not* amber.
- True alerts / destructive → **red** (`--red`).
- Keyboard focus uses a **green `:focus-visible` ring** to override the gold
  ring Windows draws by default.

Key CSS tokens (in `:root`, `src/styles.css`):
`--green #46f08a`, `--green-bright`, `--green-dim`, `--text #a7e8c4`,
`--muted`, steel `--steel-0..3` + `--bevel-hi/lo` + `--rivet`,
`--standby #8fa39a`, `--red #ff4d44`, plus `--glow-green/standby/red`.
Monospace font stack via `--mono`.

## 8. App icon

`scripts/gen-icon.js` draws the icon procedurally with **only Node built-ins
(`zlib`)** — no image libraries. It renders (with 4× supersampling) a steel
plate with corner rivets and a beveled border, a recessed CRT screen showing a
green clock at **10:10** with tick marks and a glowing bezel ring + scanlines,
then encodes PNG (raw IDAT + CRC32) and wraps it as ICO.

Outputs `build/icon.png` and `build/icon.ico`. Runs automatically via
`npm run icon` (and as the first step of `npm run build`). To restyle the icon,
edit `colorAt(x, y)`; the PNG/ICO encoder below it can be left alone.

## 9. Build procedure

```bash
npm install
npm run build      # = npm run icon && electron-builder --win
```

Produces:
- `dist/Timesheet Setup 1.0.0.exe` — the **installer** (~82 MB, NSIS, unsigned)
- `dist/win-unpacked/Timesheet.exe` — the unpacked app (~189 MB, runnable)

> Rebuild after any source change you want shipped — the `dist/` installer does
> not auto-update from source.

### ⚠️ Known build blocker: winCodeSign symlink failure on Windows

electron-builder downloads `winCodeSign-2.6.0.7z`, which contains **macOS
symlinks** (`darwin/10.12/lib/libcrypto.dylib`, `libssl.dylib`). On Windows
without symlink privilege, `7za` can't create them → exits status 2 →
electron-builder retries and **fails** (though `dist/win-unpacked` is still
produced, no installer). Error:
`Cannot create symbolic link : A required privilege is not held by the client`.

**Fixes (any one):**
1. **Enable Windows Developer Mode** (Settings → Privacy & security → For
   developers) — grants symlink privilege. Cleanest.
2. Run the build from an **elevated** terminal.
3. **Cache workaround** (what was used here): the partial extraction is actually
   Windows-complete — only the two `darwin` symlinks are missing, and they
   aren't needed for a Windows build. Copy/rename the partially-extracted folder
   to the path electron-builder expects:
   `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\winCodeSign-2.6.0`,
   remove the orphan temp dirs, and rebuild — it finds the cache and skips
   extraction.

## 10. Install behavior (one-click NSIS)

The installer is configured `oneClick: true`, `perMachine: false`. That means
**no wizard** — double-clicking `Timesheet Setup 1.0.0.exe`:
- silently installs to `%LOCALAPPDATA%\Programs\Timesheet`,
- creates a Start-Menu + desktop shortcut and an uninstaller,
- and auto-launches the app.

So the Setup `.exe` (~82 MB) and the installed `Timesheet.exe` (~189 MB) are
**different files** — the small one unpacks the big one. Uninstall via
Add/Remove Programs or `Uninstall Timesheet.exe`.

## 11. Dev workflow (no reinstall per change)

You do **not** need to rebuild/reinstall to test changes:

```bash
npm start          # = electron .  (runs the live source directly)
```

This runs the real app (real preload IPC, real disk persistence) against the
current source files. It reads/writes the **same** `timesheet.json` as the
installed app, so data is shared. Single-instance lock applies: close the
installed copy first, or `npm start` will just focus it and exit.

Loop: edit source → `npm start` → verify → repeat. Only run `npm run build`
when you want a fresh installer to ship/install.

(There's also a browser preview via `scripts/preview-server.js` +
`src/preview-shim.js`, which fakes `window.api` with `localStorage` — handy for
fast UI iteration, but it is **not** the real app and won't exercise real
file persistence or main/preload IPC.)
